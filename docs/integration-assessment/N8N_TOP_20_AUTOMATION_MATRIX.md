The evaluated source is `Zie619/n8n-workflows@94007c1445d9258a7da116646b79473e7c7c3282`. The checked-out `workflows/` directory contains 2,061 JSON files. A metadata-only parser successfully read 2,052 and rejected 9 malformed files. The parser recorded workflow name, active state, node names/types and credential type names; it did not export credential values or raw parameter payloads.

The catalog has a large execution surface: 889 parsed workflows contain HTTP Request nodes, 516 contain Code nodes, 148 contain Function-family nodes, 325 contain Webhook-family nodes, and smaller sets contain Execute Command, local-file, SSH, FTP and direct database nodes. Those counts justify a curated rebuild policy rather than bulk import.

**Classification applies to the proposed PlanThePath automation, not the source JSON as-is.** Even an **IMPLEMENT NOW** row must be reconstructed from an empty workflow, use pinned approved nodes, and pass the controls below.

## Catalog-wide controls

Every selected workflow must pass these controls, regardless of its row classification:

### Acquisition and promotion

1. Record source commit, path, name and a SHA-256 of the reviewed source file.
2. Reconstruct the workflow from an empty definition; do not import source credentials or hidden parameters.
3. Pin n8n and node versions. Permit only first-party allowlisted nodes.
4. Static-scan the exported candidate workflow and produce a human-readable node/egress/credential diff.
5. Require code review, security review, domain-owner approval and signed promotion through environments.
6. Default every new workflow to inactive. Activation is a separate audited action with a kill switch.

### Node policy

- Deny `Execute Command`, SSH, FTP, local-file reads/writes, direct Postgres/MySQL/MongoDB access, unapproved community nodes, arbitrary package loading and generic shell execution.
- Deny generic HTTP Request unless both destination and method are allowlisted and the use cannot be met by a typed connector/adapter.
- Deny Code/Function nodes by default. An exception requires source-controlled code, tests, resource limits and security review; no secrets or dynamic evaluation.
- Deny generic public webhooks for authoritative callbacks. Provider callbacks terminate at PlanThePath's native verified ingress.
- Restrict outbound DNS/IP ranges, payload size, runtime, concurrency and execution count.

### Runtime and data

- Use a dedicated non-public n8n instance in a separate account/network segment. Its database is n8n's own, never PlanThePath's.
- Store secrets in an approved secret manager; inject by reference; isolate credentials per workflow and environment; rotate and revoke them independently.
- Disable diagnostics/telemetry that can export execution data. Prune successful and failed execution payloads to the minimum approved retention.
- Send opaque identifiers and template/command references where possible. Resolve recipient or sensitive content only inside a native adapter with fresh authorization.
- Log metadata and reason codes, not tokens, raw documents, answers, resumes, prompts or message bodies.
