# V4 reuse and migration matrix

## Assessment basis

The V4 repository at `0c067ce24f92662daa933edf0fc8b75636d99469` is a Node 22 application using the built-in SQLite driver and a server-rendered HTTP interface. It has no third-party runtime dependencies. Its value is primarily its breadth of domain exploration, content corpus, governance ideas, and tests—not runtime compatibility with PlanThePath.

Each meaningful component below has exactly one disposition. **REUSE AS-IS** never means “trust without validation”; it means the artifact can be retained without changing its meaning. **MIGRATE DATA** always means transform through the governed process in the migration strategy.

## Repository and corpus findings

### Licensing and ownership

No root license was found. Third-party notices identify Apache-2.0 or MIT sources for named repositories, while registry labels include MIT, CC BY, CC BY 4.0, and CC BY-SA. The phrase `ONE Original` does not establish ownership or a license grant. Creative Commons attribution and share-alike obligations must be evaluated against how PlanThePath modifies and distributes content.

Therefore:

- repository access is not permission to copy code or content;
- each content record needs a source, license expression, attribution, source URL/reference, checksum, and clearance status;
- unknown or contradictory records remain quarantined; and
- legal/content-owner approval is a hard release gate.

### Reproducibility

Tracked V4 documentation describes a final state of 20,320 questions: 13,787 published, 6,363 draft, and 170 archived. A clean reconstruction was attempted twice in an isolated temporary clone and did not finish within the allotted time. The partial second run reached 16,985 total questions, 10,622 published, 6,363 draft, 13,045 primary mappings, 59,739 general mappings, and 95 blueprints.

This does not prove that the tracked target is wrong; it proves that migration cannot rely on prose counts or an ad hoc local database. The source owner must produce a reproducible, immutable export and a machine-verifiable manifest.

### Scoring and randomization

V4 uses fixed category weights and recent-attempt blending without sufficient evidence of calibration, model versioning, fairness, or resistance to gaming. Assessment shuffling includes `sort(() => Math.random() - 0.5)`, which is neither reproducible nor a suitable unbiased selection contract. Both are replaced in the target design.

## Disposition totals

The matrix intentionally contains very little **REUSE AS-IS**. Runtime code is in a different architecture and has unresolved ownership. Most value falls into **ADAPT**, **MIGRATE DATA**, or **REUSE AS REFERENCE**, with explicit rejection where a component would weaken identity, storage, payment, evidence, readiness, or privacy controls.
