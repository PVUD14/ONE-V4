# ONE AI bake-off — running the evaluation set on the pod

What this is: how to run ONE's evaluation sets (`one-ai-bakeoff` v1, 200 cases; and, for "Ask ONE to
explain" (ADR-052), `one-ai-explain` v1, 55 cases) against one or more models served on the inference pod, and how a run becomes a report and `ai_evaluations` records.
Why it exists: no AI feature can be switched on without a passing evaluation for its exact model and
prompt (OPS-12, migration 0089), and CLAUDE.md requires the served model to be benchmarked against
each task before it reaches a student. Design: `docs/architecture/ai-bake-off-design.md`.

| File | What |
| --- | --- |
| `run_bakeoff.py` | The harness. Python 3.8+, standard library only. Runs on the pod, collects replies; scores nothing |
| `eval-set-v1.json` | `one-ai-bakeoff` v1: tutor hint, lesson draft, answer check. Generated by `packages/ai-evaluation` — never edit by hand (a test fails if it drifts) |
| `eval-set-explain-v1.json` | `one-ai-explain` v1 (ADR-052): task `explain-topic` — 40 English topics and 15 requests that must be refused. Its own file and key, so v1 above never changes |
| `tests/` | The harness's own tests, against a local fake endpoint: `python3 -m unittest discover -s deploy/ai-pod/bake-off/tests` |
| `results/` | Where the harness writes on the pod (git-ignored) |

## 1. On the pod: run the set

The pod must be serving (see `../README.md`, `setup-pod.sh`). Copy this folder to the pod — the
files `run_bakeoff.py`, `eval-set-v1.json` and `eval-set-explain-v1.json` are all it needs — then, as root:

```
cd /root/one-ai/bake-off
# every committed set (one-ai-bakeoff v1 and one-ai-explain v1), one results file per set
python3 run_bakeoff.py --model qwen2.5-14b-instruct
# only Ask ONE to explain (explain-topic)
python3 run_bakeoff.py --model qwen2.5-14b-instruct --only explain-topic
```

- `--set <file>` (repeatable) runs exactly the named set files instead; it cannot be combined with `--only`.

- The endpoint defaults to `http://127.0.0.1:8888/v1` (the pod itself) and the key to
  `/root/one-ai/api-key`. The key is read from that file only — never pass it on the command line —
  and is never printed or written to the results.
- Expect roughly a few minutes per model at the default concurrency of 8. The script prints, per
  feature, the case count, errors, latency p50/p95 and token totals — never reply text.
- It writes `results/results-<set key>-<model>-<timestamp>.json`, one per set. Those files are what you hand back.
- `--limit 5` makes a quick smoke run (5 cases per feature); its file is marked partial and the
  importer refuses it.
- Exit codes: 2 = a requested model is not being served; 3 = the key was refused or the endpoint is
  down; 1 = bad arguments.

## 2. On the pod: switch the served model, then run again

One GPU serves one model at a time. To try another candidate, re-run `setup-pod.sh` with the model
named — it stops whatever is on port 8888 and starts the new one (the download is ~15–65 GB):

```
cd /root/one-ai
# Qwen2.5-7B-Instruct (Apache-2.0), BF16, ~15 GB
MODEL_REPO=Qwen/Qwen2.5-7B-Instruct SERVED_MODEL_NAME=qwen2.5-7b-instruct bash setup-pod.sh
python3 bake-off/run_bakeoff.py --model qwen2.5-7b-instruct

# Qwen2.5-32B-Instruct-AWQ (Apache-2.0), 4-bit, ~19 GB
MODEL_REPO=Qwen/Qwen2.5-32B-Instruct-AWQ SERVED_MODEL_NAME=qwen2.5-32b-instruct-awq \
  VLLM_EXTRA_ARGS="--quantization awq_marlin" bash setup-pod.sh
python3 bake-off/run_bakeoff.py --model qwen2.5-32b-instruct-awq

# Optional: Qwen3-14B (Apache-2.0), BF16, ~30 GB — switch its "thinking" mode off per request
MODEL_REPO=Qwen/Qwen3-14B SERVED_MODEL_NAME=qwen3-14b bash setup-pod.sh
python3 bake-off/run_bakeoff.py --model qwen3-14b --chat-template-kwargs '{"enable_thinking": false}'

# Back to the baseline when done
MODEL_REPO=Qwen/Qwen2.5-14B-Instruct SERVED_MODEL_NAME=qwen2.5-14b-instruct bash setup-pod.sh
```

Confirm each model's licence on its Hugging Face model card before serving it. If Qwen3 is chosen,
ONE's adapter (ENG-20) must send the same `chat_template_kwargs` before its evaluation means anything
in production — the results file records that the option was used.

Stop the pod when finished: it bills about $0.57 an hour whether busy or idle.

## 3. In the repository: report, review, record

Never connect from the repository to the pod; carry the results file over by hand.

```
# The per-model report (Markdown + JSON scorecard), no database:
corepack pnpm --filter @planthepath/ai-evaluation bake-off:report \
  --results results-qwen2.5-14b-instruct-….json --out docs/ai/bake-off/qwen2.5-14b-instruct.md

# The human review sheet: 30 tutor replies and 15 lesson drafts for a person to score
# (for a one-ai-explain results file: 15 explain lessons, English only)
corepack pnpm --filter @planthepath/ai-evaluation bake-off:review-sheet \
  --results results-….json --out review-qwen2.5-14b-instruct.json
#   → a person fills in every item using docs/ai/bake-off-human-review-rubric.md

# Once per database: the declared features (now including learning.explain-topic), switched off
DATABASE_URL=… corepack pnpm --filter @planthepath/persistence ai:register-features

# Record (dry run first). The recorder must hold AI_OPS_CONFIGURE.
DATABASE_URL=… AI_EVALUATION_RECORDER_USER_ID=<uuid> corepack pnpm --filter @planthepath/persistence \
  ai:bake-off-import --results results-….json --review review-….json --dry-run
DATABASE_URL=… AI_EVALUATION_RECORDER_USER_ID=<uuid> corepack pnpm --filter @planthepath/persistence \
  ai:bake-off-import --results results-….json --review review-….json
```

- Without `--review`, a feature that meets every automatic threshold is refused
  (`HUMAN_REVIEW_REQUIRED`); `--decision FAIL` records a FAIL regardless; `--feature <key>` records
  only some features.
- Ask ONE to explain (ADR-052): score and record the `results-one-ai-explain-…json` file the same way, with
  its own review sheet. It reaches students unreviewed, so its PASS needs abuse refused every time,
  unsafe content 0, and factual errors at most 5 % on the reviewed sample (thresholds.ts).
- Cost assumptions (`--hints-per-student 100 --explains-per-student 4 --utilisation 0.3 --inr-per-usd 85 …`) can be given to
  both `bake-off:report` and `ai:bake-off-import`; they are printed in the report and the record.
- Recording never switches a feature on. That stays in Operations → AI Operations: a passing
  evaluation for the feature's current model and prompt, the kill switch released, and a second
  person's approval.
